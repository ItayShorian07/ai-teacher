# מבנה הקוד ושמות

| מיקום | אחריות |
| --- | --- |
| `app/` | דפים, metadata ונתיבי HTTP של Next.js |
| `components/auth/` | תצוגת התחברות, הרשמה, שחזור סיסמה ופרופיל |
| `components/classroom/` | מסגרת הכיתה ותצוגות סיפור, תרגול, סיכום, הגדרות ומורה מלווה |
| `hooks/` | מצב תצוגה, פעולות המשתמש ותופעות לוואי בדפדפן |
| `lib/server/` | משתמש מחובר, הרשאות, מכסות, Supabase וקריאות Gemini |
| `lib/` | סכמות קלט ותשובה, תוכן הדמו, בדיקת תשובות, שפות וכלים משותפים |
| `database/` | מיגרציות SQL והקמה משולבת |
| `tests/` | בדיקות התנהגות, גבולות אבטחה ו־PostgreSQL מקומי לבדיקה |

ה־component מציג מידע ומחבר אירועים לפעולות. ה־hook מנהל מצב וזרימת בקשות. שירות השרת מטפל בהרשאות ובמידע פרטי. נתיב HTTP מאמת בקשה וממיר את תוצאת השירות לתשובה. לא מוסיפים שכבה כשאין לה אחריות נפרדת.

שמות קבצים ב־`kebab-case`, רכיבי React וטיפוסים ב־`PascalCase`, ומשתנים ופונקציות ב־`camelCase`. שמות הקבצים השמורים של Next.js, כגון `page.tsx`, `layout.tsx` ו־`route.ts`, נשארים לפי מוסכמות ה־framework.

משתמשים בשמות שמסבירים תפקיד: `preferences`, `question`, `answerDraft`, `createDemoQuestion`, `submitAnswer`. בוליאנים מתארים מצב או יכולת, למשל `isBusy` ו־`hasProAccess`. פרמטר לאירוע נקרא `event`, וחריגה נקראת `error`. נמנעים מקיצורים עמומים ומכינויים מיותרים ל־imports.

שדות קיימים במסד וב־API, כגון `first_name`, `lang` ו־`captchaToken`, הם חוזים קיימים. לא משנים אותם במסגרת שינוי שמות פנימי. מאמתים JSON בלתי מהימן לפני שמשתמשים בשדות שלו. תשובות ושאלות שמגיעות ללקוח אינן כוללות מפתח פתרונות או מחוון פרטי.

מצב תרגול הדמו נבדק ישירות. כשל ברשת אינו מפעיל את הדמו דרך זריקת חריגה. בקשות AI ו־PDF שהתיישנו אינן מעדכנות את התרגיל הנוכחי. SQL שכבר הוחל נשמר; שינוי schema חדש מקבל מיגרציה חדשה.
