# הפעלת משתמשים, שם משתמש וסיסמה

נבדק ב־20.10.2026: האתר החי החזיר `configured:false` ב־`/api/account/status`. פירוש הדבר הוא שחסרים בו לפחות אחד משני משתני החיבור הציבוריים ל־Supabase. קובץ `.env.example` אינו מפעיל משתני סביבה ב־Vercel. כתובת Supabase מהעותק המקומי הישן לא נפתרה ב־DNS; אין בכך הוכחה שהפרויקט נמחק, ויש לבדוק את כתובתו ואת מצבו בלוח הבקרה.

בדיקה חוזרת ב־22.10.2026 מצאה את שמות כל משתני השירות בעותק המקומי הנוסף של הפרויקט, אך הכתובת `tfxmxfcxcknezdvupnan.supabase.co` עדיין החזירה `ENOTFOUND`. לא הועתקו סודות ל־Git, ולא בוצעו שינויי ניהול בפרויקט Supabase או משלוח הודעות. צריך לאמת שהכתובת שהוגדרה עדכנית ושהפרויקט פעיל לפני בדיקת כניסה חיה.

## מה מוכן בקוד

- `/login`: שם משתמש או מייל וסיסמה; אפשר גם קוד למייל ו־Google, כאשר הספקים מוגדרים.
- `/register`: שם משתמש, סיסמה ואימות סיסמה, מייל, שם פרטי ומשפחה, עיר/יישוב, גיל, טלפון ובית ספר. תחביבים אופציונליים.
- `/account/complete`: השלמת פרטים ובחירת שם משתמש גם למשתמשי Google ולחשבונות קיימים.
- `/forgot-password`: בקשת איפוס למייל, אימות קוד ובחירת סיסמה חדשה.
- `/account/password`: יעד מוגן לקישור איפוס, וגם הגדרת סיסמה לחשבון מחובר.
- `/account`: צפייה בפרטים, עריכה, עדכון סיסמה, יציאה ומחיקה.
- `/classroom`: למידה למשתמש מאומת עם פרופיל מלא. `/demo` נשאר דמו מקומי נפרד.

שם המשתמש נשמר באותיות קטנות: 3–30 תווים, אותיות באנגלית, ספרות וקו תחתון, מתחיל באות. האינדקס במסד הנתונים מונע כפילויות גם בבקשות מקבילות. השם נתפס רק כשהמשתמש המאומת שומר את הפרופיל; אם נתפס בינתיים, מבקשים ממנו לבחור אחר. הסיסמה נשמרת ומאומתת רק ב־Supabase Auth, ואינה נכנסת לפרופיל או ללוגים של האפליקציה.

## חיבורים הנדרשים להפעלה

1. **Supabase פעיל** — העתיקו את Project URL והמפתח הציבורי מהפרויקט הנכון. אם הפרויקט מושהה, הפעילו אותו דרך לוח הבקרה.
2. **סכמת נתונים** — בפרויקט חדש הריצו `database/setup.sql`. בפרויקט שכבר עודכן לגרסה הקודמת הריצו רק `database/005_username_login.sql`. אין מחיקה של משתמשים קיימים. משתמש ללא שם משתמש יופנה להשלמת פרטים בכניסה הבאה.
3. **Vercel → Settings → Environment Variables → Production** — הגדירו:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` — שרת בלבד; משמש לאיתור פרטי כניסה לפי שם משתמש ולמכסת הניסיונות.
   - `NEXT_PUBLIC_SITE_URL=https://ai-teacher-three-pied.vercel.app`
   - `NEXT_PUBLIC_TURNSTILE_SITE_KEY`
   - `TURNSTILE_SECRET_KEY`
4. **Supabase Auth** — הפעילו ספק Email, הרשמה ואימות מייל. הגדירו אורך סיסמה מינימלי 12 תווים גם אצל הספק. הגדירו SMTP כדי לאפשר משלוח לציבור, ולא רק לתיבות בדיקה מאושרות.
5. **תבניות מייל** — בתבניות Confirm signup, Magic Link ו־Reset Password הציגו `{{ .Token }}` כדי לאפשר הקלדת קוד באתר. ניתן להשאיר גם את קישור האימות/האיפוס.
6. **כתובות חזרה** — הוסיפו ב־Supabase את:
   - `https://ai-teacher-three-pied.vercel.app/auth/callback`
   - `https://ai-teacher-three-pied.vercel.app/auth/callback?next=password`
   ולבדיקה מקומית את המקבילות עם `http://127.0.0.1:3100`.
7. **Turnstile** — אשרו את דומיין האתר, והפעילו CAPTCHA גם ב־Supabase Auth. הספק מאמת את האסימון פעם אחת בכל בקשת כניסה/הרשמה; האפליקציה אינה צורכת אותו קודם לכן. בכניסה ללמידה יש אתגר נפרד.
8. **Redeploy** — משתני `NEXT_PUBLIC_` מוטמעים בבנייה; צריך פריסה חדשה אחרי הגדרתם.

ל־Google יש להגדיר Client ID ו־Client Secret ב־Supabase ואת כתובת החזרה ש־Supabase מספק ב־Google. אין צורך ב־Google או ב־Gemini כדי להפעיל כניסה בשם משתמש וסיסמה.

אין להדביק מפתחות סודיים בצ׳אט, בקובץ הדוגמה או ב־GitHub. אפשר להשלים את ההגדרות דרך חיבורים מאושרים ל־Supabase ול־Vercel, או בלוחות הבקרה.

## הגנת ההתחברות

המרת שם המשתמש למייל נעשית בשרת בלבד באמצעות פונקציה שחסומה למפתחות ציבוריים ולמשתמשים רגילים. הסיסמה עדיין נבדקת ב־Supabase, ולא במפתח הניהול. הודעת כישלון אינה מבחינה בין שם משתמש לא קיים לסיסמה שגויה. כתובת המייל שנמצאה אינה נשלחת לדפדפן.

יש בדיקת מקור לבקשות, הגבלת גודל, CAPTCHA, וכן מכסות אטומיות במסד: עד 10 ניסיונות ב־15 דקות למזהה כניסה ועד 100 לרשת. כתובת IP נלקחת מכותרת ש־Vercel דורס; במארח אחר משתמשים במכסת רשת משותפת עד להגדרת proxy מהימן. במונה נשמר HMAC, לא כתובת גולמית. הפעלה ללא תשתית המכסות נכשלת בבטחה.

הנתיב `/account/password` דורש התחברות ואימות מייל. שחזור דרך קוד מאמת זהות ב־Supabase; הממשק מוודא שהזהות לא התחלפה בין האימות לעדכון. לאחר שינוי סיסמה מתבקשת יציאה מכל המכשירים; אסימוני גישה שכבר הונפקו עשויים להישאר בתוקף עד פקיעתם לפי הגדרות Supabase.

## בדיקות וגבולות

`npm test` כולל בדיקת SQL במסד PostgreSQL מקומי מוטמע: ייחודיות שמות, חסימת איתור מייל למשתמש רגיל, בידוד פרופילים ומכסת כניסה. הבדיקות אינן יוצרות משתמשים בשירות החי ואינן שולחות מיילים. `npm run check:connections` בודק הגדרות וטבלאות בלי להדפיס סודות.

אחרי החיבור יש לבדוק בפועל: הרשמה עם שני מיילים שבשליטתכם, קוד שגוי/תקין, שם כפול, כניסה בשם ובמייל, איפוס סיסמה, משתמש קיים, Google, רענון ויציאה, וגישה אסורה לפרופיל האחר. בדיקות אלה עדיין לא הושלמו מול השירות החי.

מקורות: [סיסמאות ב־Supabase](https://supabase.com/docs/guides/auth/passwords), [CAPTCHA](https://supabase.com/docs/guides/auth/auth-captcha), [כותרות בקשה ב־Vercel](https://vercel.com/docs/headers/request-headers).
