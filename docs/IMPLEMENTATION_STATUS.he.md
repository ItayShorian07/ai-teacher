## בדיקה קודמת בשירות החי (לפני עדכון ה־env)

בוצעה בדיקת קריאה בלבד באמצעות המפתח הציבורי שבסביבה המקומית:

- Supabase Auth מחזיר HTTP 200. הרשמה במייל מופעלת.
- Google וטלפון/SMS כבויים בהגדרות Auth.
- `profiles`, `material_chunks`, `question_items`, `story_cache`, `entitlements` החזירו `PGRST205`: הטבלה אינה קיימת ב־schema cache של הפרויקט.
- בסביבה המקומית חסרים `GEMINI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`.
- לא בוצעו הרשמה, משלוח מייל, Google OAuth, מחיקת משתמש או קריאה בתשלום ל־Gemini. לא התקבלה גישת ניהול לשירות. אין להסיק מהצלחת הקוד שהחיבורים הללו פעילים.

לאחר הבדיקה הועברו ההגדרות שמולאו בקובץ הדוגמה אל `.env.local` המוחרג מ־Git. קובץ הדוגמה מכיל שמות משתנים בלבד. בבדיקה חוזרת לאחר העדכון כל משתני הסביבה נקראו, אך טבלאות הפרויקט עדיין החזירו PGRST205 ו־Google נשאר כבוי. בדיקה עדכנית: `npm run check:connections`. בסביבת Vercel צריך להגדיר את המשתנים בנפרד.

## כמה מסדי נתונים צריכים?

**אחד: Supabase Postgres עם pgvector.** אין צורך ב־Pinecone או בשני פרויקטי Supabase נוספים.

שלושה אוספי תוכן בתוך אותו DB:

1. `material_chunks` — חומר לימוד מאושר והמקורות שלו.
2. `question_items` ו־`question_rubrics` — שאלות מאושרות ומחוונים פרטיים.
3. `learning_cache` — סיפורים ושאלות שנוצרו, כולל embeddings. אחזור המטמון הוא לפי מפתח מדויק כדי לא להחזיר סיפור בנושא או בתחביב שגוי. `story_cache` נשמרת לתאימות למיגרציה הישנה; השירות החדש משתמש ב־learning_cache בלבד.

בנוסף: `profiles`, `entitlements`, `learning_questions` ו־`ai_quota`. המכסה האטומית היא 30 פעולות tutor/OCR לשעה למשתמש, כולל בקשות למטמון. השגיאה היא 429 בחריגה ו־503 אם תשתית המכסה אינה זמינה. לא קיימת עקיפה דרך fallback למודל.

`learning_questions` שומרת את השאלה והמחוון לצורך בדיקה מאובטחת. סיכום התקדמות עדיין נשמר בזיכרון הדפדפן למפגש בלבד. אם רוצים היסטוריית התקדמות בין מכשירים, צריך טבלת attempts/mastery נוספת **באותו DB**. שמירת PDF לטווח ארוך תדרוש bucket פרטי; כרגע ה־PDF נשלח ל־Gemini ואינו נשמר באתר.

## הפעלה

1. הריצו את [database/setup.sql](../database/setup.sql) ב־SQL Editor של הפרויקט. הקובץ מרוכז ועסקתי, אינו מוחק נתוני משתמשים, ומכיל את כל המיגרציות. הנתונים הפרטיים מוגנים ב־RLS והרשאות טבלאות/פונקציות. חשוב לבדוק זאת גם מול שני משתמשי בדיקה לאחר ההפעלה.
2. הגדירו `.env.local` ובסביבת האירוח לפי `.env.example`. מפתח השרת והמפתח ל־Gemini אינם משתני `NEXT_PUBLIC_`. יש להחליף את ערך Gemini שהיה בקובץ הדוגמה; הסרתו מהקובץ אינה מוחקת אותו מהיסטוריית Git.
3. ב־Supabase הגדירו SMTP למשלוח מיילים ואת תבנית OTP עם `{{ .Token }}`. הגדירו Google Provider ו־OAuth redirect allowlist עבור `/auth/callback`. הגדירו `NEXT_PUBLIC_SITE_URL` בהתאם לכתובת הפריסה.
4. הגדירו Turnstile לדומיין האתר, הכניסו את המפתח הציבורי והסודי, והפעילו CAPTCHA ב־Supabase Auth. בלי הגנת בוטים/מפתח שרת/מפתח AI, שירותי AI נשארים חסומים. כפתורי ההתחברות נפתחים רק אחרי שקיימות טבלת פרופילים והגדרות Turnstile. עצם הצגת widget אינה מונעת פנייה ישירה ל־Supabase; ההפעלה אצל הספק הכרחית.
5. אשרו והכניסו חומר מקורי או מורשה לטבלאות התוכן. לשימוש בווקטורים: `gemini-embedding-001`, 1536 ממדים; אין לערבב וקטורים קיימים שנוצרו במודל אחר. רשומות מאושרות ללא וקטור עדיין נשלפות לפי התאמה מדויקת של נושא ושפה. אם המאגר ריק, ההסבר מסומן כתוכן AI מקורי, ללא מקור לימודי מאושר.
6. להענקת Pro, השתמשו בדוגמת SQL בסוף `004_learning_services.sql` עם מזהה המשתמש. המשתמש אינו יכול להעניק לעצמו Pro.
7. הריצו `node scripts/check-connections.mjs`, `npm test`, `npm run build`. לבדיקת נתיבים מקומית הפעילו `npm run dev -- --port 3100` ובחלון נפרד `node scripts/check-routes.mjs`.

הטלפון הוא שדה קשר חובה ב־POC, אך **לא מוצג כמאומת**. אימות SMS נשאר endpoint אופציונלי; האימות קושר את המספר המאומת לאותו משתמש. הפיכתו לחובת הרשמה תחייב ספק SMS ושינוי זרימת onboarding.

## מגבלות בדיקה וארכיטקטורה

העוזר בודק קוד באמצעות המודל; הוא אינו מריץ קוד תלמידים. הרצת קוד ובדיקות יחידה מחייבות sandbox מבודד נפרד. אין לטעון שקוד הורץ או שהמחוון מבטיח נכונות. PDF נבדק לפי סוג, גודל וחתימת קובץ; אין כאן מנוע PDF מקומי לבדיקת מספר עמודים. מסמכי פרטיות/תנאי שימוש לא נוספו משום שנשארו לבדיקה לפי הבקשה הקודמת.

הבדיקות המקומיות מכסות ולידציה, 540 צירופי תרגילי דמו, אסימון בוטים מזויף/שפג תוקפו/משתמש אחר, הגנות על קלט AI, PDF גדול או מתחזה, ואימות טלפון לאותו חשבון. נדרשת בדיקת קצה־לקצה לאחר חיבור הספקים, כולל הרשמה עם שני חשבונות, בידוד נתונים, CAPTCHA, Pro, PDF, מטמון ומחיקה. בדיקת ממשק חזותית בדפדפן לא התאפשרה בשל הרשאות Computer Use במחשב.

מקורות רשמיים: [Supabase CAPTCHA](https://supabase.com/docs/guides/auth/auth-captcha), [מחיקת משתמש](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser), [Turnstile Siteverify](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [Gemini PDF](https://ai.google.dev/gemini-api/docs/document-processing), [Gemini embeddings](https://ai.google.dev/gemini-api/docs/embeddings).
